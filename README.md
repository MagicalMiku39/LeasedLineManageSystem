# LeasedLineManageSystem

专线台账管理系统，使用 React、Express 和 SQLite，支持台账导入、客户经理统计及集团收入分析。

## 本地运行

建议使用 Node.js 24。安装依赖后运行 `npm run build`，Windows 使用 `start-https.cmd`，Ubuntu 参考 `Ubuntu服务器部署说明.md`。默认 HTTPS 端口为 3443，首次使用需要设置账号及 Google Authenticator。

## 导入概览

登录后打开“台账”。“运营中心 → 导入概览”汇总最近一次台账导入：KPI 进度（净增、距目标还差、每月需净增、计入预计后还差），待处理事项（待确认的 KPI 落地、未标注的欠费预警、新流失的战客集团），这次导入的各类变更，以及渗透状态发生变化的战客集团，每项都可以点进处理它的页面。导入台账后，提示条上也有“查看导入概览”。导入记录在“台账”下，设置在右上角齿轮图标。

## 集团收入

1. 进入“集团收入”，点击顶部“导入 Excel”，上传 BOSS Excel 并检查收入预览，再确认导入。
2. 月份取报表“月份”列，默认最新已导入月份。客户经理默认选择现有 18 人，清空可查看全部。
3. 点击客户经理查看集团，点击集团查看产品收入、月度趋势、当前台账和核对信息。
4. 延伸服务在集团详情登记：报表已包含的服务不重复增加收入；报表未包含且已确认的收入按 6% 除税后单列补充。报表修订后需复核补录。

报表收入为信息化收入；台账资费为含税出账收入。专线卫士按 6%、其他产品按 9% 换算预计信息化收入。无历史快照、未完成产品映射时只提供当前台账推算，不能视为历史准确对账。金额使用原表单位。

KPI 开关影响关联台账的数量与预计金额，集团报表总收入不截断为 KPI 产品范围。专线延伸服务独立展示，不增加专线数量。

## 欠费预警邮件

1. 依赖中包含腾讯官方 `@tencent-qqmail/agently-cli`，执行 `npm install` 或 `npm ci` 一并安装对应平台的 CLI。
2. 在**运行系统服务的同一操作系统账户**下执行 `npm run mail:login`，打开命令输出的原始链接完成 OAuth；用 `npm run mail:status` 查看授权状态。Windows PowerShell 使用 `npm.cmd`。Ubuntu systemd 的运行用户需单独授权，OpenClaw 或另一台电脑中的授权不会自动迁移。
3. 进入“运营中心 → 客户经理邮箱”，选择经理、填写收件邮箱并保存。优先使用台账工号匹配，没有工号时才使用姓名；相同姓名但工号不同的经理需分别设置。
4. 点击专线条目的“提醒”，核对收件人、报告主题和欠费明细后点击“发送报告”。每封报告仅包含当前这一条专线，提交成功才将条目标为提醒。“已提交发送”表示腾讯接受发送请求，不等于收件人已收到或阅读。
5. 预览 15 分钟有效。邮箱、专线信息变更时需重新预览；相同报告成功提交后不重复发送。失败或结果待核实时可查看最近发送记录，再通过 [Agent Mail 管理端](https://agent.qq.com) 核实。系统不会自动重发不确定的请求。
6. 所有预警邮件强制带默认抄送，地址仅配置在服务器 `data/mail-settings.json` 的 `defaultCc` 数组中，不写入源码。也可通过 `WARNING_MAIL_CC` 环境变量配置（多个地址用分号分隔），或用 `AGENT_MAIL_SETTINGS_FILE` 指定其他本地配置文件。配置缺失或无效时拒绝发送，预览会展示抄送对象；配置变更后需重新预览。

安装及授权参考[腾讯官方接入文档](https://agent.qq.com/doc/cli-setup.md)。OAuth 凭据由 CLI 保存在服务账户环境，项目不读取或复制令牌；客户经理邮箱与发送记录保存在 SQLite 中。迁移或发布代码时继续排除这些本地数据与授权凭据。

## 集团与集团档案

1. 顶部菜单“集团”列出全量集团清单中的全部集团，以及台账里有专线但清单中没有的集团（标“未在清单”）。可按名称、编码、客户经理搜索，按专线情况（有在用 / 无在用 / 未开通）、标记（战客、要客、客户经理不一致、未在清单）和集团级别筛选；“导出”跟随当前筛选。
2. 导入全量集团清单：在“集团”页点击顶部“导入 Excel”。系统读取含“集团编码、集团名称、集团客户经理名称”三列的工作表（有多张时取名称含“全量”的一张）；带“客户类别”列的工作表作为要客清单，把类别（要客、139要客）标到对应集团；其余工作表不读取。预览后确认，每次导入整份替换上一版清单，替换前自动备份。
3. 客户经理以台账为准：集团在台账中有专线时，取名下专线最多的客户经理；没有专线时用清单中的客户经理。两边不一致的集团会标出清单登记的客户经理，可用“客户经理与台账不一致”筛选查看。
4. 点击集团进入集团档案：概况、专线（状态与产品分布、专线列表）、欠费销户风险、收入趋势、KPI 预计任务、最近导入变化。微网格、入网时间、成员数等默认收起，点“显示更多信息”查看。台账、欠费销户预警、KPI达成、战客专线渗透、集团收入和专线详情里的集团编码都可以点进档案。

## 填报链接

需要客户经理补充台账信息、更新商机进度或上报商机时，不用给他们开账号：

1. 在“运营中心 → 填报链接”选客户经理、可填写的内容和有效期，点“生成链接”，复制后发给本人。链接只显示这一次。
2. 对方打开链接就是填报页，不用登录，只能看到和填写自己名下的内容：在用专线的合同、资费、联系人等补充信息，名下商机的进展，以及新商机的上报。
3. 到期自动失效，也可以在列表里随时“作废”。每次填写都记在“填报记录”里，台账改动同时记入专线详情的修改记录。
4. 默认情况下链接和系统是同一个地址，对方需要在能打开本系统的网络内使用。要让客户经理在外网（手机）也能打开，在“设置 → 访问控制 → 填报端口”开启单独的对外端口并填写对外填报地址：这个端口上只有填报页，没有登录页和其他任何页面。说明见 [Ubuntu 服务器部署说明](Ubuntu服务器部署说明.md) 第 12 节。
5. 要发给多位客户经理时，切到“批量生成并邮件发送”：勾选客户经理后，系统为每人生成各自的链接并分别发邮件（不抄送）。邮箱在“欠费销户预警 → 客户经理邮箱”中设置。邮件里的链接地址取你当时打开系统所用的地址。

## 潜客清单

1. 在“集团”页右上角切换到“潜客清单”。潜客是没有在用专线的集团：“未开通专线”指台账中没有它的专线，“已流失”指曾有专线、现已全部销户。
2. 默认排序：战客、要客在前，再按集团级别、企业员工数、成员出账金额。这些数据来自全量集团清单，没有的显示“—”并排在后面。
3. “客户经理”视图是每位客户经理名下的潜客数量；“集团”视图里可以标跟进状态（已联系 / 暂不跟进 / 已排除）和备注，标为“已排除”的不再出现。
4. 点“登记预计新增”会跳到 KPI达成并带入该集团。

## 欠费预警汇总发送

在“运营中心 → 欠费销户预警”点“汇总发送”：系统按当前统计日期为每位客户经理生成一封邮件，列出其名下全部欠费停机专线（不含已标“忽略”的），并附本月和本年度净增。生成不会发送；勾选收件人后点击发送，逐个显示结果，发送后这些专线标为“提醒”。默认在邮件末尾附上该客户经理的专属填报链接（7 天有效，可取消勾选），对方可以直接点进去补充台账信息、更新商机进度。客户经理邮箱和默认抄送沿用单条提醒的设置。

## 战客专线渗透

0. 没有单独导入过战客清单时，使用全量集团清单中标识为“战客”的集团；导入战客清单后以战客清单为准。

1. 进入“运营中心 → 战客专线渗透”，点击顶部“导入 Excel”，下载模板，填写集团编码、集团名称、客户经理（三列必填），预览后确认。每次导入整份替换上一版战客清单。
2. 已渗透：集团有在用专线（正常在用、停机执行中、停机）；已流失：没有在用专线、有销户专线；未渗透：两者都没有。回退和临时生成资料的专线不计入。KPI 开关同样生效。
3. “集团”视图可按渗透状态（含“未渗透+已流失”）筛选，点击集团查看名下专线；“客户经理”视图是各经理的战客渗透率报表。

## 修改密码

在“设置 → 账号与密码”（右上角齿轮图标）修改登录密码：填写当前密码、Google Authenticator 验证码和两次新密码（至少 8 个字符）。修改后其他设备上的登录会退出，当前页面保持登录；验证码绑定不变。输错与登录共用次数，连续 5 次锁定 15 分钟。每次修改和失败都记入安全日志。

## 数据备份与回退

每次导入台账、替换战客清单或全量集团清单之前，以及每周一次，系统自动备份整个数据库到 `data/backups/`。在“设置 → 备份与恢复”（右上角齿轮图标）可以下载备份，或把台账类数据、战客清单、全量集团清单分别回退到某份备份；回退前会先备份当前数据，可以撤销。下载和回退都需要验证码。说明见 [Ubuntu 服务器部署说明](Ubuntu服务器部署说明.md) 第 9 节。

## 动态 IP 访问

固定 IP 通过防火墙白名单访问主端口。IP 不固定的设备可以走单独的设备证书端口：在系统的“设置 → 访问控制”开启，只接受持有本系统签发证书的连接，登录要求不变；可逐台签发和吊销。步骤见 [Ubuntu 服务器部署说明](Ubuntu服务器部署说明.md) 第 11 节。

## 验证与数据

运行 `npm test` 与 `npm run build`。测试使用独立临时数据库。`data/`（含 `data/backups/`）、`uploads/`、`certs/` 与浏览器验证截图均排除 Git，不随代码发布业务数据。
